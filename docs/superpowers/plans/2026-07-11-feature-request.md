# Feature Request Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a standalone Settings feature-request flow that stores authenticated, categorized requests of 10–300 characters in PostgreSQL.

**Architecture:** A dedicated `feature_requests` table and Spring service own persistence and server-side validation. `SupportController` exposes one authenticated create endpoint that derives ownership from the JWT. The Expo app adds a focused screen and mutation while reusing the existing support data layer and Settings visual language.

**Tech Stack:** PostgreSQL/Flyway, Spring Boot 3.5, Spring Data JPA, Jakarta Validation, JUnit 5/Mockito, Expo Router, React Native, TanStack Query, TypeScript.

## Global Constraints

- “Feature Request” is a standalone Settings section and must not be grouped under Help & Legal.
- User-entered message is required and must contain 10–300 characters after trimming.
- Categories are `CHALLENGES`, `COMMUNITY`, `PROGRESS_AND_STATS`, `APP_EXPERIENCE`, and `OTHER`.
- Ownership comes only from the authenticated JWT principal; no request `userId` is accepted.
- No screenshots, title field, voting, history, list endpoint, or admin UI.
- Failed submissions retain the draft; successful submissions clear it only after persistence succeeds.
- Preserve unrelated changes in both dirty worktrees.

- [ ] **Step 3: Add the Flyway migration**

```sql
CREATE TABLE IF NOT EXISTS challengesphere.feature_requests (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES challengesphere.users(id) ON DELETE CASCADE,
    category VARCHAR(40) NOT NULL,
    message VARCHAR(300) NOT NULL,
    app_version VARCHAR(80),
    platform VARCHAR(80),
    device_info VARCHAR(200),
    status VARCHAR(30) NOT NULL DEFAULT 'NEW',
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_feature_requests_category CHECK (category IN ('CHALLENGES','COMMUNITY','PROGRESS_AND_STATS','APP_EXPERIENCE','OTHER')),
    CONSTRAINT chk_feature_requests_message_length CHECK (char_length(btrim(message)) BETWEEN 10 AND 300),
    CONSTRAINT chk_feature_requests_status CHECK (status IN ('NEW','REVIEWING','PLANNED','DECLINED','COMPLETED'))
);

CREATE INDEX IF NOT EXISTS idx_feature_requests_user_created
    ON challengesphere.feature_requests (user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_feature_requests_status_created
    ON challengesphere.feature_requests (status, created_at DESC);
```

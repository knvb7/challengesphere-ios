# App Support Design

## Goal

Add an in-app App Support flow where signed-in users can describe a question or issue, attach screenshots, and submit the request directly to the ChallengeSphere support inbox at `ironside-dev@challengesphere.com`.

## Scope

This feature covers authenticated in-app support tickets only. It does not add ticket persistence, admin dashboards, user-facing ticket history, or two-way support messaging inside the app. Delivery is email-based.

## User Experience

Users reach App Support from Settings and from the Help Center's Contact Support action. The screen uses the existing dark visual language and shows a compact support form with:

- issue type: question, bug, account, challenge, media upload, other
- subject
- message
- up to 3 screenshots from gallery or camera
- submit button with uploading/submitting progress

After a successful submit, the app shows a confirmation and clears the form. If upload or email submission fails, the form preserves user input and shows a retryable error.

## Frontend Architecture

Add a route at `app/app-support.tsx` that renders a new `screens/AppSupport.tsx` screen. The screen reuses `MediaSourceChooser` for camera/gallery selection and keeps local screenshot previews with remove controls.

Add `services/supportService.ts` for API calls:

- `generateSupportPresignedUrls(userId, mediaFiles)` calls `POST /support/presigned-urls`
- `createSupportTicket(payload)` calls `POST /support/tickets`

Add a small React Query mutation hook in `hooks/useSupport.ts` if it keeps the screen simpler. Keep the hook focused on support ticket submission rather than introducing a broad support state layer.

Extend frontend media types with `SUPPORT_SCREENSHOT` and reuse existing direct S3 upload helpers where possible. Screenshots should be images only and should use the same file URI upload behavior already proven for submissions and challenge covers.

## Backend Architecture

Add:

- `SupportController` under `/api/v1/support`
- `CreateSupportTicketRequest`
- `SupportTicketResponse`
- `SupportService` and `SupportServiceImpl`

Authenticated endpoints:

- `POST /api/v1/support/presigned-urls`
- `POST /api/v1/support/tickets`

Security stays simple: both endpoints require a valid JWT like other non-auth application endpoints. The controller uses `@AuthenticationPrincipal UserPrincipal` and does not trust a user id passed from the client for ownership.

Add `SUPPORT_SCREENSHOT` to backend `MediaTypes`. Support presigned URLs write to S3 keys shaped like:

`support/user_{userId}/screenshots/{timestamp}_{uuid}.{ext}`

The support ticket endpoint validates the current user, validates the subject/message, accepts up to 3 screenshot object keys generated by the support upload flow, creates time-limited signed read links for the support email, and sends the email through the existing `EmailService`.

## Email Format

Send one email to `ironside-dev@challengesphere.com`.

Subject:

`[ChallengeSphere Support] {issueType}: {subject}`

Body includes:

- user id
- username
- email id
- issue type
- subject
- message
- app/platform/device context provided by the app when available
- screenshot signed read links plus object keys
- submitted timestamp

The email should use escaped text for user-provided values. Screenshots are signed read links, not attachments, to avoid mobile upload fragility and email attachment limits. Include object keys next to links so support can still identify the stored evidence after links expire.

## Data Flow

1. User opens App Support from Settings or Help Center.
2. User fills issue type, subject, message, and optionally selects screenshots.
3. App requests support presigned URLs for selected screenshots.
4. App uploads screenshot files directly to S3.
5. App submits the ticket request with text fields and uploaded screenshot locations.
6. Backend resolves the authenticated user, formats the support email, and sends it to `ironside-dev@challengesphere.com`.
7. App shows success or preserves the draft on failure.

## Validation And Limits

Frontend:

- subject: required, 3 to 120 characters
- message: required, 10 to 4000 characters
- issue type: required, defaults to bug or question
- screenshots: max 3 images

Backend:

- enforce the same subject, message, issue type, and screenshot count limits
- reject unsupported screenshot content types for support presigned URLs
- do not log raw support message bodies or full screenshot URLs

## Error Handling

If screenshot upload fails, show an upload-specific error and let the user retry without clearing the form. If ticket submission fails, preserve the uploaded screenshot references and let the user retry. If backend mail is disabled or SMTP fails, the API should return a failure instead of pretending delivery succeeded.

The existing backend currently has `app.mail.enabled=false` in local/prod properties. Implementation should make support email delivery depend on the configured mail setting, and deployment must enable SMTP before this is considered live.

## Testing

Frontend tests/scripts should check that:

- Settings links Contact Us/App Support to the in-app route, not `mailto:`
- Help Center Contact Support links to the in-app route
- App Support validates required fields
- screenshot count is capped at 3
- submit calls support upload and ticket services in order

Backend tests should check that:

- unauthenticated support endpoints are rejected
- authenticated ticket submission sends email to `ironside-dev@challengesphere.com`
- invalid subject/message/screenshot counts are rejected
- support presigned URLs use the support S3 prefix
- the support service does not log raw message bodies

## Non-Goals

- no public unauthenticated support form
- no support ticket database table
- no support status tracking
- no automatic screenshot capture of the app UI
- no real-time chat

What changes in the app

The upload photo area gets a new LeetCode proof mode for coding challenges. After sync, the user can preview the day’s problems and tap Create proof post.

  • ✓Add LeetCode proof preview to challenge details after sync.
  • ✓Create a reusable proof card component for feed and submission timeline.
  • ✓Keep normal image posts untouched for non-coding challenges.

What changes in the backend

Submissions need a durable proof field so other users can see the same LeetCode card after it is posted.

  • ✓Add proof_payload JSON/text column to submissions.
  • ✓Accept proof payload in create and reupload submission APIs.
  • ✓Return proof payload from feed, timeline, and submission detail APIs.

Posting rule

For LeetCode proof posts, media can be empty only when a valid LeetCode proof payload exists. Empty normal posts should still be blocked.

Data Flow

The important bit is that proof is not just local UI. It is saved with the submission and comes back anywhere submissions are rendered.

Frontend

Challenge details

Sync LeetCode, filter activity by challenge day, preview found problems.

API

Create submission

Send caption, day number, optional media, and LeetCode proof payload.

Backend

Persist proof

Save JSON proof on the submission row and return it in all read models.

Feed

Render proof card

If proof provider is LeetCode, render this card instead of image media.

Implementation Steps

This is the concrete order I would use so the feature lands safely without breaking existing photo submissions.

1. Backend schema Add submission proof payload storage and expose it through response DTOs.
2. Frontend types Add LeetCode proof payload types to submission and feed models.
3. Proof composer Filter synced LeetCode activity by day and create a proof submission.
4. Feed renderer Render the special proof card wherever submissions are shown.
